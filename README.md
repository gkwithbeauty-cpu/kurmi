# Kurmi

**A community-built engine for evidence-based reconciliation of public information.**

Kurmi is an open invitation to build tools that help compare records across sources, surface meaningful discrepancies, preserve evidence, and support accountable human review. The long-term direction is intentionally community-shaped: no single contributor owns the architecture, and proposals are evaluated in the open.

## The invitation

Help define what this project should become. Start with a question, a data source, a test, a design sketch, a careful critique, or a small implementation. The roadmap is a set of hypotheses—not a decree.

## Principles

- **Evidence before conclusions.** Every finding should be traceable to source observations.
- **Uncertainty is data.** Preserve confidence, provenance, freshness, and disagreement.
- **Humans stay accountable.** Automation may assist review; consequential actions require explicit authorization and auditability.
- **Privacy by design.** Minimize collection, protect sensitive data, and document lawful use.
- **Open governance.** Architecture evolves through public proposals, review, and documented decisions.
- **Small, verifiable steps.** Prefer reproducible tests and reversible changes.

## Current state

Kurmi is at the project-definition and foundation stage. Interfaces and architecture are provisional. Nothing here should be treated as production-ready or as an authoritative decision system.

## Join in

1. Read [CONTRIBUTING.md](CONTRIBUTING.md) and [GOVERNANCE.md](GOVERNANCE.md).
2. Browse the [roadmap](docs/ROADMAP.md) and open issues.
3. Propose an idea or pick a scoped task.
4. Discuss risky or cross-cutting changes before investing in implementation.
5. Submit a pull request with tests, evidence, and clear limitations.

## Safety boundary

Kurmi is intended for transparent, lawful, accountable reconciliation. It must not be used to expose private personal data, enable harassment, bypass access controls, or trigger consequential changes without authorized human review. Data-source integrations must document permission, terms, retention, and privacy risks.
