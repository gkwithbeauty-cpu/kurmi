# Contributing to Kurmi

Contributions are welcome across code, research, documentation, design, testing, accessibility, security, and community care.

## Start small
1. Read the README, specification, roadmap, governance, and security notes.
2. Search existing issues before opening a duplicate.
3. For large changes, open an issue or discussion first.
4. State the problem, assumptions, alternatives, risks, and how success will be tested.
5. Keep pull requests focused and explain how reviewers can verify them.

## Contribution types
- Good first issue: bounded tasks that need little domain context.
- Research: compare approaches and document sources, uncertainty, and trade-offs.
- Data source: propose only sources whose access is lawful and permitted; document terms, rate limits, retention, and privacy risks.
- Engineering: include tests, error handling, observability, and migration notes where relevant.
- Governance: challenge assumptions respectfully and propose better processes.

## Pull request checklist
- [ ] The change addresses a linked issue or explains why one was unnecessary.
- [ ] Tests cover intended behavior and relevant failure cases.
- [ ] Documentation and examples are updated.
- [ ] No credentials, private data, or real sensitive records are included.
- [ ] Security, privacy, bias, and misuse implications are considered.
- [ ] Limitations and unresolved questions are stated.

Assume good intent, critique ideas rather than people, welcome dissent, and make decisions legible.
